# PrusaSlicer 3 INDX "JRH" vendor — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A generated PrusaSlicer 3.0.0-alpha12 vendor, `hyigerINDX`, whose one
printer "Prusa CORE One INDX 8T JRH" has tools 1–7 at Prusa's HF0.4 and a tool 8
that can be HF0.4, standard 0.4 (TPU), HF0.6 (PC-CF) or standard 0.25
(detailed PLA/PETG), with every preset Prusa offers the INDX today copied in.

**Architecture:** PS3 resolves inheritance only inside one vendor, and only a
vendor's `vendor.yaml` can declare tools or printer configurations. So
`tools/build_ps3_vendor.py` snapshots the INDX-relevant part of Prusa's
installed 1.0.20 YAML verbatim into our own vendor directory, adds a generated
`vendor.yaml`, and appends the new nozzles' `tool_print` and `filament` presets,
ported from the sources this repo's 2.9 build already uses. Every key it writes
is checked against PS3's own option table. `tools/install_ps3.py` copies the
result into the PrusaSlicer3-dev data folder and migrates the user's presets.

**Tech Stack:** Python 3.12, PyYAML 6 (read only; output is emitted by our own
writer), `unittest`.

**Spec:** the design agreed in conversation on 2026-10-31, recorded in the
"Decisions" section below. No separate spec file.

## Decisions (from the conversation)

- Tools 1–7 are always Prusa HF0.4. Only tool 8 is swapped.
- Tool 8 offers HF0.4 (default), standard 0.4 (Bondtech flexibles tool, TPU),
  HF0.6 (Bondtech CHT, PC-CF), standard 0.25 (Bondtech fine, PLA/PETG detail).
  HF0.8 and HF1.0 stay in the 2.9 bundle only.
- One printer; tool 8 is picked per session (alpha12 forgets slot choices on
  restart, issue #15737).
- Own vendor, not a patch of Prusa's files; copies of all of today's Prusa INDX
  presets, plus migrated copies of the user's calibrated presets.
- Printer preset name "Prusa CORE One INDX 8T JRH" (user's explicit request; one
  constant, so rule 4 can be applied with a one-line change).
- All PS3 output is marked UNVALIDATED until printed in PS3.

## Global Constraints

- Prusa PS3 profile pin: `1.0.20` (`vendor.yaml` `version:`); refuse on any other.
- PrusaResearch.ini pin for 2.9-sourced values: `2.5.12`; refuse on any other.
- Never invent a value. Each new value is copied from a named Prusa preset or a
  committed repo artifact, or held from a named neighbour with a reason string.
- Every emitted key must exist in `tools/ps3_keydefs.tsv` for its location:
  tool_print keys need `Tool` in overrides; filament keys need location
  `Filament` or `Filament` in overrides. Otherwise refuse, unless the key is in an
  explicit drop/rename table with a reason.
- Output is byte-for-byte deterministic (ids from `uuid5`, sorted iteration).
- No preset id contains `@` (crashes alpha12 on restart).
- Commits authored `hyiger <43388146+hyiger@users.noreply.github.com>`.
- The 2.9 artifacts (`vendor/`, `printer/`, `filaments/`) must not change.

## Review Focus

1. A Prusa INDX filament branch gaining a non-0.4 variant upstream would
   duplicate our tool-8 presets → the coverage check must refuse (Task 3 test).
2. A copied Prusa document referencing an id we did not copy aborts alpha12 at
   startup → the closure check must refuse (Task 3 test).
3. 2.9 filament start G-code that is not exactly the `M572`/`M573 R` pattern
   would silently lose or double pressure advance → refuse (Task 4 test).
4. A YAML scalar our writer leaves unquoted that YAML reads as another type
   (`0x0`, `12:30`, `yes`, `#FF8000`) → writer round-trip test (Task 1).
5. Re-running install over an existing install must not duplicate or delete
   the user's own presets in our vendor's user folder (Task 6 test).

### Task 4: tool_print and filament ports

**Interfaces:**
- `TOOL_PRINT_SOURCES`: HF0.4 `0.07` held from PS3 `0.10mm Fine @COREONEINDX 0.4HF`
  (reason: tools 1–7 only need a preset at 0.07 so a 0.25 tool 8 can print it);
  standard 0.4 = deep copy of PS3's HF0.4 subtree, renamed `@COREONEINDX 0.4`;
  0.25 = 2.5.12 `0.07mm Extra Fine`, `0.10mm Fine ★`, `0.15mm Detail @COREONEINDX 0.25`
  resolved; HF0.6 = repo `0.20mm Detail` / `0.25mm Balanced ★ @COREONEINDX HF0.6`
  resolved. Leaves carry every Tool-overridable key of the resolved profile.
- `RENAME_2TO3`, `DROP_2TO3` (key → reason). Print-only keys that differ from
  PS3's INDX print base are listed in the file header, not written.
- `port_filament(section: dict) -> (values, features)`: drops 2.9 bookkeeping,
  renames `filament_retract_*`/`filament_wipe`/`filament_travel_*`/
  `filament_deretract_speed` to the plain key (nil → omitted); start G-code
  `M572 S<x> ; Pressure advance\nM573 R[rest]` → `pressure_advance:
  automatic_calibration`, `pressure_advance_value: x`, `start_filament_gcode` =
  rest or `'; Filament g-code'`; `M572 S0 ; Pressure advance\n…` without `M573 R`
  → `pressure_advance: disabled`, G-code verbatim; anything else refuses.
- Filament ports: tool-8 sizes Prusa's PS3 does not cover — HF0.6 (repo 0.6
  bundle), 0.25 (repo 0.25 bundle), standard 0.4 (repo 0.4 bundle, only
  materials with no PS3 INDX coverage). One file per material,
  `preset-filament-hyiger-<material>.yaml`, condition
  `printer.base_model == "COREONE_INDX"`, explicit leaf names, final `*quit*`.
  `features` from the material's PS3 doc chain, else `$.type` from `filament_type`.
